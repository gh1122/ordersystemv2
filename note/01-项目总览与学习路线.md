# 01 - 订单系统项目总览与学习路线

> 面向前端开发者的 Spring Boot 综合练习项目

---

## 一、项目定位

这是一个**刻意练习项目**，目的是把 Spring Boot 企业级开发的核心知识点串成一个完整的业务系统。

**前端类比**：就像你学前端时做的"后台管理系统"综合练习，把路由、状态管理、权限、组件库等串起来。

---

## 二、功能模块与知识点映射

### 模块 1：用户认证（Token 体系）

| 功能 | 涉及知识点 |
|------|-----------|
| 注册 | Service 分层、密码加密（BCrypt）、参数校验 |
| 登录 | JWT 签发、Redis 存登录态 |
| 修改密码 | Service 业务逻辑、缓存清除 |
| 注销 | Redis 删除登录态、Token 黑名单 |
| Token 刷新 | 拦截器自动续期 |

**前端类比**：
- JWT ≈ 前端存的 token（localStorage 里的那个）
- Redis 存登录态 ≈ 后端的"登录状态"，比前端存 token 更安全
- 拦截器 ≈ 前端路由守卫（`beforeEach` 检查登录）

### 模块 2：用户管理（CRUD）

| 功能 | 涉及知识点 |
|------|-----------|
| 用户列表 | MyBatis-Plus 分页插件（IPage） |
| 新增/编辑 | Entity ↔ DTO 转换、参数校验 |
| 删除 | 逻辑删除（@TableLogic） |
| 搜索 | Wrapper 条件构造器（QueryWrapper） |

**前端类比**：
- MyBatis-Plus ≈ Prisma / TypeORM（ORM 框架）
- Wrapper ≈ 前端的查询条件拼接（`{ name, age, ...filters }`）
- 分页插件 ≈ 前端表格的分页逻辑（pageNum + pageSize）

### 模块 3：权限管理（RBAC）

| 功能 | 涉及知识点 |
|------|-----------|
| 角色管理 | 多表关联查询 |
| 菜单管理 | 树形结构（递归/父子关系） |
| 动态菜单 | 根据角色返回不同菜单列表 |
| 接口权限 | 自定义注解 + 拦截器 |

**前端类比**：
- RBAC ≈ 前端动态路由（不同角色注册不同路由）
- 动态菜单 ≈ 根据权限过滤侧边栏菜单
- @RequireRole 注解 ≈ 路由 meta 里的 `roles: ['admin']`

### 模块 4：订单系统（综合）

| 功能 | 涉及知识点 |
|------|-----------|
| 订单创建 | **事务**（@Transactional，多表操作） |
| 订单查询 | **聚合函数**（COUNT/SUM/AVG/GROUP BY） |
| 订单超时取消 | **定时任务**（@Scheduled） |
| 订单通知 | **Kafka**（异步消息） |
| 库存扣减 | Redis 分布式锁 / 乐观锁 |

**前端类比**：
- 事务 ≈ 前端"要么全部成功要么全部失败"（但数据库事务是原子的）
- 定时任务 ≈ `setInterval` 轮询，但更可靠
- Kafka ≈ 前端的事件总线（EventBus），但是跨服务的

## 四、学习阶段规划

### 阶段一：项目搭建（第 1 天）

**目标**：跑通基础框架

- [ ] 创建 Spring Boot 项目（Maven）
- [ ] 配置 application.yml（MySQL/Redis/Kafka）
- [ ] Docker Compose 启动三个中间件
- [ ] 编写 init.sql 建表脚本
- [ ] 跑通"Hello World"接口

**产出**：项目能启动，能访问一个测试接口

### 阶段二：认证体系（第 2-3 天）

**目标**：跑通注册登录 + JWT

- [ ] 用户表 Entity + Mapper
- [ ] JWT 工具类（签发/校验/刷新）
- [ ] 注册接口（BCrypt 加密）
- [ ] 登录接口（签发 Token + Redis 存登录态）
- [ ] JWT 拦截器（校验 Token）
- [ ] 全局异常处理（@RestControllerAdvice）

**产出**：能用 Postman 测试注册→登录→访问受保护接口

### 阶段三：用户管理（第 4 天）

**目标**：跑通 CRUD + 分页

- [ ] 用户列表（分页 + 多条件搜索）
- [ ] 新增/编辑用户
- [ ] 删除用户（逻辑删除）
- [ ] Entity → VO 转换

**产出**：完整的用户管理后端接口

### 阶段四：权限系统（第 5-6 天）

**目标**：跑通 RBAC + 动态菜单

- [ ] 角色表、菜单表、关联表
- [ ] 用户-角色-菜单多表查询
- [ ] 动态菜单接口（树形返回）
- [ ] @RequireRole 自定义注解
- [ ] 拦截器校验角色权限

**产出**：不同角色登录看到不同菜单、不同接口权限

### 阶段五：订单系统（第 7-9 天）

**目标**：跑通事务 + 聚合 + 定时任务 + Kafka

- [ ] 订单表、订单明细表、商品表
- [ ] 创建订单（事务：扣库存 + 创建订单 + 创建明细）
- [ ] 订单统计（聚合函数 + GROUP BY）
- [ ] 定时任务：超时订单自动取消
- [ ] Kafka：订单创建后异步发通知

**产出**：完整的订单业务流程

### 阶段六：跨域与联调（第 10 天）

**目标**：前端能调通

- [ ] CORS 全局配置
- [ ] Session/Token 联调测试
- [ ] 接口文档整理

**产出**：前端项目能跨域调用所有接口

## 五、核心概念速查（前端类比版）

| 后端概念 | 前端类比 | 一句话解释 |
|---------|---------|-----------|
| Spring Bean | 单例对象 | Spring 容器管理的实例 |
| 依赖注入（DI） | props 注入 | 框架自动把依赖"注入"进来，不用自己 new |
| AOP | 高阶组件 / 装饰器 | 在不改原代码的情况下加功能（日志、事务） |
| Controller | 路由处理函数 | 接收请求，返回响应 |
| Service | 业务逻辑函数 | 处理核心业务 |
| Repository/Mapper | API 请求函数 | 负责拿数据 |
| Interceptor | 路由守卫 beforeEach | 请求到达 Controller 前拦截 |
| Filter | axios 拦截器 | 最外层拦截（跨域、编码） |
| JWT | localStorage token | 无状态鉴权令牌 |
| @Transactional | 原子操作 | 要么全成功，要么全回滚 |
| @Scheduled | setInterval | 定时执行的任务 |
| Kafka | EventBus（跨服务） | 异步消息队列 |
| Redis | 前端缓存 / SessionStorage | 内存数据库，快 |
| CORS | 跨域配置 | 允许不同源的请求 |
| 聚合函数 | array.reduce | 对一组数据汇总计算 |

## 六、数据库表结构预览

```sql
-- 用户表
CREATE TABLE t_user (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  username VARCHAR(50) NOT NULL UNIQUE,
  password VARCHAR(100) NOT NULL,  -- BCrypt 加密后存储
  nickname VARCHAR(50),
  status TINYINT DEFAULT 1,        -- 1启用 0禁用
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted TINYINT DEFAULT 0         -- 逻辑删除
);

-- 角色表
CREATE TABLE t_role (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  role_name VARCHAR(50) NOT NULL,   -- 如 ROLE_ADMIN
  role_desc VARCHAR(100)
);

-- 菜单表
CREATE TABLE t_menu (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  parent_id BIGINT DEFAULT 0,       -- 父菜单ID，0表示顶级
  menu_name VARCHAR(50),
  menu_path VARCHAR(100),           -- 路由路径
  icon VARCHAR(50),
  sort_order INT DEFAULT 0
);

-- 用户-角色关联
CREATE TABLE t_user_role (
  user_id BIGINT,
  role_id BIGINT,
  PRIMARY KEY (user_id, role_id)
);

-- 角色-菜单关联
CREATE TABLE t_role_menu (
  role_id BIGINT,
  menu_id BIGINT,
  PRIMARY KEY (role_id, menu_id)
);

-- 商品表
CREATE TABLE t_product (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(100),
  price DECIMAL(10,2),
  stock INT                         -- 库存
);

-- 订单表
CREATE TABLE t_order (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  order_no VARCHAR(32) UNIQUE,      -- 订单号
  user_id BIGINT,
  total_amount DECIMAL(10,2),
  status TINYINT,                   -- 0待支付 1已支付 2已取消
  create_time DATETIME,
  update_time DATETIME
);

-- 订单明细表
CREATE TABLE t_order_item (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  order_id BIGINT,
  product_id BIGINT,
  quantity INT,
  price DECIMAL(10,2)
);
```

## 七、学习建议

1. **先跑通，再理解**：不要一开始就纠结原理，先让代码跑起来
2. **每写一个接口，用 Postman 测试**：就像前端写完组件看页面效果
3. **遇到报错先看控制台**：Java 的报错信息通常很详细
4. **记笔记**：每个知识点写一篇笔记，沿用 `序号-主题.md` 格式
5. **类比前端**：遇到新概念先想"前端里有没有类似的东西"
