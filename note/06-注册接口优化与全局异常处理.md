# 06 - 注册接口优化与全局异常处理

> 日期：2026-09-02

---

## 一、今日完成

### 1. 统一错误码（ErrorCode 枚举）

新建 `model/enums/ErrorCode.java`，给每种错误编号：

```java
public enum ErrorCode {
    SUCCESS(200, "操作成功"),
    PARAM_ERROR(400, "参数错误"),
    SYSTEM_ERROR(500, "系统异常"),

    // 用户模块 10xx
    USERNAME_EXISTS(1001, "用户名已存在"),
    USERNAME_EMPTY(1002, "用户名不能为空"),
    PASSWORD_LENGTH_ERROR(1003, "密码长度必须在6到20位之间"),
    PASSWORD_NOT_MATCH(1004, "确认密码与密码不一致");
}
```

**为什么用错误码？**
- 前端判断 `code === 1001` 比判断 `message === "用户名已存在"` 更稳定
- 改文案不影响前端逻辑
- 类比前端：用常量 `const ERR_USERNAME_EXISTS = 1001`，不用魔法数字

### 2. BaseVo 改造

加上 `code` 字段，`error()` 方法支持传入具体错误信息：

```java
@Data
public class BaseVo<T> {
    private int code;       // 新增：错误码
    private boolean success;
    private String message;
    private T data;

    // 重载：支持自定义错误信息
    public static <T> BaseVo<T> error(int code, String message) { ... }
}
```

**泛型 `<T>` 解释**：

```java
public static <T> BaseVo<T> success(T data)
//          ↑           ↑
//          |           └─ 返回值里的 data 是 T 类型
//          └─ 声明 T 是泛型（不声明编译器不认识）
```

类比 TypeScript：`function success<T>(data: T): ApiResponse<T>`

### 3. 全局异常处理

新建两个文件：

| 文件 | 作用 |
|------|------|
| `BusinessException.java` | 自定义业务异常，携带 ErrorCode |
| `GlobalExceptionHandler.java` | 统一拦截所有异常，返回 BaseVo 格式 |

**GlobalExceptionHandler 处理三种异常**：

| 异常类型 | 场景 | 返回 |
|---------|------|------|
| `MethodArgumentNotValidException` | @Valid 校验失败 | 400 + 具体字段错误 |
| `BusinessException` | 业务规则不通过 | 对应错误码 + 信息 |
| `Exception` | 兜底（系统异常） | 500 + "系统异常" |

**前端类比**：
- `@RestControllerAdvice` ≈ axios 响应拦截器 / React ErrorBoundary
- 不管哪里报错，统一返回 `{ code, success, message, data }` 格式

---

### 4. Controller 加 @Valid

```java
// 之前
public BaseVo<UserVo> register(@RequestBody UserRegisterDTO dto)

// 改成
public BaseVo<UserVo> register(@Valid @RequestBody UserRegisterDTO dto)
```

加 `@Valid` 后，Spring 自动执行 DTO 上的校验注解（`@NotBlank`、`@Size`）。

---

### 5. DTO 校验注解加 message

```java
@NotBlank(message = "用户名不能为空")
private String username;

@NotBlank(message = "密码不能为空")
@Size(min = 6, max = 20, message = "密码长度必须在6到20位之间")
private String password;

@NotBlank(message = "确认密码不能为空")
private String confirmPassword;
```

不写 `message` 时，默认只返回 `"不能为空"`，不知道是哪个字段。

---

### 6. Service 精简

`@Valid` 已经处理了格式校验，Service 里重复的手动校验可以删掉：

```java
// ❌ 删掉 —— @Valid 已经做了
if (username == null || username.isEmpty()) { ... }
if (password == null || password.length() < 6) { ... }

// ✅ 保留 —— 业务规则，@Valid 管不了
if (existingUser != null) {
    return BaseVo.error(ErrorCode.USERNAME_EXISTS, "用户名已存在");
}
```

## 四、知识点总结

| 知识点 | 说明 | 前端类比 |
|--------|------|---------|
| 错误码枚举 | 给每种错误编号 | `const ERR_XXX = 1001` |
| `@Valid` | 触发 DTO 参数校验 | 调用 `form.validate()` |
| `@RestControllerAdvice` | 全局异常拦截 | axios 拦截器 / ErrorBoundary |
| `@ExceptionHandler` | 处理特定异常类型 | `catch (e instanceof X)` |
| `BusinessException` | 自定义业务异常 | `class ApiError extends Error` |
| DTO message | 校验失败时的提示 | 表单校验的 `message` 配置 |
| 泛型 `<T>` | 类型占位符，延迟指定 | TypeScript 的 `<T>` |
